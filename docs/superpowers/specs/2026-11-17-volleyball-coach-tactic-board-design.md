# 排球教练战术板 3D 设计规格

## 目标

交付一个离线优先的 Unity 6 LTS 横屏 Android 教练战术板。教练可以从战术库新建或复制战术，摆放六名己方球员，编排发球、一传、二传、进攻与掩护，使用统一时间轴回放，并在顶视、斜上方和网侧三种机位之间切换。

本机未安装 Unity Editor，因此本阶段交付可打开的 Unity 工程源码、Editor 场景生成脚本、示例数据、测试代码和复现说明；Unity Editor、Android APK、真机性能和触控验收结果均在 README 中标记为待执行。

## 方案

工程采用单一 Unity 项目和分层 C# 代码。`Domain` 只依赖可序列化 DTO 与纯计算规则；`Application` 负责时间评估、回放时钟、验证和复制；`Presentation` 把确定性评估结果映射到 3D 场景、动画与 uGUI；`Infrastructure` 负责 JSON 存档和内置示例。

核心链路为：

```text
TacticDocument JSON -> TacticValidator -> TacticEvaluator.EvaluateAt(timeMs)
                        -> PlaybackClock -> Scene/Animator/Ball/Trail adapters
                        -> Library + Editor UI -> JsonTacticRepository
```

`EvaluateAt` 是无副作用的确定性函数。球员地面位置由移动段曲线驱动，姿态由动作片段进度驱动，球由共享触球端点和三维弧线驱动；播放和 Seek 都只调用同一评估入口。

## 数据与校验

`TacticDocument` 带 `schemaVersion`，包含球场配置、球员定义、初始站位、阶段、移动段、姿态动作、触球事件和球路。时间使用非负毫秒，坐标使用米，所有引用使用稳定 ID。保存前执行草稿级或可回放级校验，检查 ID 唯一、引用存在、时间有效、同一球不重叠飞行、共享触球连续、过网高度和球员移动重叠。

存档按战术 ID 命名，写入同目录临时文件和 `.bak`，再替换目标文件。坏档单独报告，不阻塞其他战术。复制是深拷贝并重分配内部 ID，原战术不受影响。

## 体验与交互

战术库提供新建、打开、重命名、复制、删除和内置示例复制。编辑器用球场主视图，顶部显示标题、保存、预览与机位，底部是阶段条；动作编辑使用可折叠面板。站位模式支持选中、拖拽、号码/角色/朝向/接发设置。编排模式使用“选球员 → 点目标 → 确认”，并显示实线跑位箭头和虚线球路。撤销/重做记录一次完整拖拽。

回放支持播放、暂停、重播、0.5×/1×、Seek、阶段跳转和机位切换。暂停切机位不推进时间，前后台切换时暂停。所有提示和空状态使用简体中文。

## 3D 内容

场地使用 1 unit = 1 m，网在 `z=0`，己方在负 Z。Editor 菜单生成球场线、球网、球、号码标签和六个低模 Humanoid 角色。角色使用共享骨骼与可采样动作片段；没有外部资产依赖，避免运行时联网。默认示例覆盖接发、二传、主攻扣球和副攻掩护的重叠动作。

## 测试与验收

EditMode 测试覆盖移动插值、移动间隙、共享触球端点、过网检查、坏数据、JSON 往返和复制隔离。PlayMode 测试覆盖示例加载、播放/Seek 一致性、触球锚点和换机位不重置时钟。真机步骤记录在 README，若没有设备不得宣称 FPS 或 APK 已验证。

## 非目标

首版不做账号、联网同步、视频导出、AI 自动编排、正式规则判罚、对方六人编排和真实动捕。
